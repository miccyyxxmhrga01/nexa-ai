<<<PROMPT>>>
My pygame game runs way too fast on my PC and slow on my friend's laptop. How do I make it the same speed everywhere?
<<<PROMPT>>>
the player in my pygame game moves super fast, how do i slow it down properly
<<<ANSWER>>>
Two things: cap the frame rate with a `Clock`, and move by speed × time instead of a fixed number of pixels per frame. Then the speed is the same no matter how fast the PC is:

```python
import pygame

pygame.init()
WIDTH, HEIGHT = 800, 600
screen = pygame.display.set_mode((WIDTH, HEIGHT))
clock = pygame.time.Clock()

x = 100.0
SPEED = 200  # pixels per SECOND, not per frame

running = True
while running:
    dt = clock.tick(60) / 1000  # caps at 60 FPS and returns the seconds since last frame

    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    keys = pygame.key.get_pressed()
    if keys[pygame.K_RIGHT]:
        x += SPEED * dt
    if keys[pygame.K_LEFT]:
        x -= SPEED * dt
    x = max(20, min(WIDTH - 20, x))

    screen.fill((25, 25, 35))
    pygame.draw.circle(screen, (250, 200, 60), (round(x), HEIGHT // 2), 20)
    pygame.display.flip()

pygame.quit()
```

How it works:
- `clock.tick(60)` waits so the loop runs at most 60 times a second.
- It also returns how many milliseconds the last frame took; dividing by 1000 gives seconds (`dt`).
- `SPEED * dt` means 200 pixels every second whether the game runs at 30 or 144 FPS. To slow the player down, just lower `SPEED`.


Press space to shoot. If you'd rather keep `remove()`, loop over a copy: `for bullet in bullets[:]:`.

<<<PROMPT>>>
When I rotate my image in pygame every frame it gets bigger and blurrier and wobbles around.

image = pygame.transform.rotate(image, 2)
screen.blit(image, (300, 200))
<<<ANSWER>>>
Two problems:
1. You rotate the already-rotated image again each frame. Every rotation adds padding and blur, so it grows and gets fuzzy. Always rotate the **original** image by the total angle.
2. A rotated image is a different size, so drawing it at the same top-left corner makes it wobble. Center its rect on a fixed point instead.

```python
import pygame

pygame.init()
screen = pygame.display.set_mode((800, 600))
clock = pygame.time.Clock()

original = pygame.Surface((120, 60), pygame.SRCALPHA)  # stand-in for your image
original.fill((240, 160, 40))
pygame.draw.rect(original, (40, 40, 40), (90, 15, 20, 30))  # a mark so you can see it turn

angle = 0
center = (400, 300)

running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    angle = (angle + 2) % 360
    rotated = pygame.transform.rotate(original, angle)  # rotate the original every time
    rect = rotated.get_rect(center=center)              # keep the same center

    screen.fill((25, 25, 35))
    screen.blit(rotated, rect)
    pygame.display.flip()
    clock.tick(60)

pygame.quit()
```

`pygame.transform.rotate()` turns counterclockwise for positive angles.

<<<PROMPT>>>
ValueError: invalid color argument when I do screen.fill((300, 0, 0))
<<<ANSWER>>>
Each part of a color must be from 0 to 255, and 300 is too big. Red at full strength is `(255, 0, 0)`.

If you compute colors (for example from a timer), clamp them so they can't leave that range:

```python
import math
import pygame

pygame.init()
screen = pygame.display.set_mode((640, 480))
clock = pygame.time.Clock()


def clamp(value):
    return max(0, min(255, int(value)))


t = 0.0
running = True
while running:
    dt = clock.tick(60) / 1000
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    t += dt
    red = clamp(128 + 160 * math.sin(t))  # would go past 255 without clamp()
    screen.fill((red, 30, 60))
    pygame.display.flip()

pygame.quit()
```

Negative numbers cause the same error, which `clamp()` also prevents.
