<<<PROMPT>>>
Simulate a planet orbiting a star in VPython using Newton's law of gravity.
<<<PROMPT>>>
Make an elliptical orbit simulation in VPython and graph the energy.
<<<ANSWER>>>
Each step: compute the gravity force, update the momentum, then the position. Starting the planet slower than the circular-orbit speed gives an ellipse:

```python
from vpython import *

scene.title = "A planet orbiting a star"
scene.background = color.black

G = 1  # simulation units keep the numbers simple
star = sphere(pos=vector(0, 0, 0), radius=0.6, color=color.yellow, emissive=True)
star.mass = 1000
planet = sphere(pos=vector(10, 0, 0), radius=0.25, color=color.cyan, make_trail=True)
planet.mass = 1
# Circular speed here is sqrt(G*M/r) = 10; a bit less makes an ellipse
planet.momentum = planet.mass * vector(0, 8, 0)

energy = graph(title="Energy", xtitle="time", ytitle="energy", height=250)
kinetic = gcurve(graph=energy, color=color.red, label="kinetic")
potential = gcurve(graph=energy, color=color.blue, label="potential")
total = gcurve(graph=energy, color=color.green, label="total")

dt = 0.002
t = 0
step = 0
while True:
    rate(500)
    r = planet.pos - star.pos
    force = -G * star.mass * planet.mass * r.hat / mag2(r)
    planet.momentum = planet.momentum + force * dt                   # update momentum first...
    planet.pos = planet.pos + planet.momentum / planet.mass * dt     # ...then position
    t += dt
    step += 1

    if step % 20 == 0:  # plotting every step would slow it down
        ke = mag2(planet.momentum) / (2 * planet.mass)
        pe = -G * star.mass * planet.mass / mag(r)
        kinetic.plot(t, ke)
        potential.plot(t, pe)
        total.plot(t, ke + pe)
```

How it works:
- `r.hat` is the unit vector from the star to the planet, so `-G*M*m*r.hat/mag2(r)` is gravity pointing back at the star.
- Updating momentum before position (Euler-Cromer) keeps the orbit closed. Doing it the other way around makes the planet slowly spiral outward.
- The green total-energy line stays flat while kinetic and potential trade places, which is a good check that the simulation is right.

<<<PROMPT>>>
Simulate a binary star system in VPython where two stars orbit each other.
<<<ANSWER>>>
Both stars pull on each other with equal and opposite forces. If their momenta start equal and opposite, the center of mass stays still and they circle around it:

```python
from vpython import *

scene.title = "Binary stars"
scene.background = color.black
scene.range = 12

G = 1
star1 = sphere(pos=vector(-4, 0, 0), radius=0.8, color=color.orange, emissive=True, make_trail=True, retain=400)
star2 = sphere(pos=vector(6, 0, 0), radius=0.6, color=color.cyan, emissive=True, make_trail=True, retain=400)
star1.mass = 300
star2.mass = 200  # center of mass: (300*-4 + 200*6) / 500 = 0

# About 850 would give circles; a bit less gives ellipses
star1.momentum = vector(0, -800, 0)
star2.momentum = -star1.momentum  # total momentum is zero
center = sphere(pos=vector(0, 0, 0), radius=0.08, color=color.white)

dt = 0.002
while True:
    rate(500)
    r = star2.pos - star1.pos
    force_on_2 = -G * star1.mass * star2.mass * r.hat / mag2(r)
    star2.momentum = star2.momentum + force_on_2 * dt
    star1.momentum = star1.momentum - force_on_2 * dt  # Newton's third law

    star1.pos = star1.pos + star1.momentum / star1.mass * dt
    star2.pos = star2.pos + star2.momentum / star2.mass * dt
    center.pos = (star1.mass * star1.pos + star2.mass * star2.pos) / (star1.mass + star2.mass)
```

The small white dot is the center of mass. It stays put, because no outside force acts on the pair. The heavier star moves on the smaller orbit.

For a circular orbit, each star's speed comes from `v_rel = sqrt(G*(m1 + m2)/d)`, where d is the distance between them: star 1 moves at `v_rel * m2/(m1 + m2)`.

Simulate two masses connected by springs between two walls in VPython (coupled oscillators).

Three springs: wall to mass 1, mass 1 to mass 2, and mass 2 to wall. Each spring pushes or pulls by `k × stretch` along its own direction. I draw the springs as `helix` objects and update their `pos` and `axis` every step:

```python
from vpython import *

scene.title = "Coupled oscillators"
scene.range = 8

k = 20      # spring constant (N/m)
L0 = 4      # relaxed spring length (m)
m = 1       # each mass (kg)

wall_left = box(pos=vector(-6.1, 0, 0), size=vector(0.2, 2, 2), color=color.gray(0.6))
wall_right = box(pos=vector(6.1, 0, 0), size=vector(0.2, 2, 2), color=color.gray(0.6))
left_anchor = vector(-6, 0, 0)
right_anchor = vector(6, 0, 0)

mass1 = box(pos=vector(-1, 0, 0), size=vector(0.8, 0.8, 0.8), color=color.red)  # pulled 1 m right

mass2.velocity = vector(0, 0, 0)

spring1 = helix(pos=left_anchor, axis=mass1.pos - left_anchor, radius=0.3, coils=10, thickness=0.05)
spring2 = helix(pos=mass1.pos, axis=mass2.pos - mass1.pos, radius=0.3, coils=10, thickness=0.05)
spring3 = helix(pos=mass2.pos, axis=right_anchor - mass2.pos, radius=0.3, coils=10, thickness=0.05)


def spring_force(other_end, this_end):
    """Force on this_end from a spring that runs from other_end to this_end."""
    s = this_end - other_end
    return -k * (mag(s) - L0) * s.hat


plot = graph(title="Positions", xtitle="t (s)", ytitle="x (m)", height=250)
x1 = gcurve(graph=plot, color=color.red, label="mass 1")
x2 = gcurve(graph=plot, color=color.blue, label="mass 2")

dt = 0.002
t = 0
step = 0
while True:
    rate(500)
    f1 = spring_force(left_anchor, mass1.pos) + spring_force(mass2.pos, mass1.pos)
    f2 = spring_force(mass1.pos, mass2.pos) + spring_force(right_anchor, mass2.pos)
    mass1.velocity = mass1.velocity + f1 / m * dt
    mass2.velocity = mass2.velocity + f2 / m * dt
    mass1.pos = mass1.pos + mass1.velocity * dt
    mass2.pos = mass2.pos + mass2.velocity * dt

    spring1.axis = mass1.pos - left_anchor
    spring2.pos = mass1.pos
    spring2.axis = mass2.pos - mass1.pos
    spring3.pos = mass2.pos
    spring3.axis = right_anchor - mass2.pos

    t += dt
    step += 1
    if step % 10 == 0:
        x1.plot(t, mass1.pos.x)
        x2.plot(t, mass2.pos.x)
```

Watch the graph: the motion passes back and forth between the two masses. That's the beat pattern of two coupled oscillators.

<<<PROMPT>>>
Make a double pendulum simulation in VPython.
<<<PROMPT>>>
Simulate chaotic motion with a double pendulum in VPython.
<<<ANSWER>>>
A double pendulum is a pendulum hanging from another pendulum. Its equations of motion come from Lagrangian mechanics; the angles are measured from straight down:

```python
from vpython import *

scene.title = "Double pendulum"
scene.range = 2.5

g = 9.8
L1, L2 = 1.0, 1.0   # rod lengths (m)
m1, m2 = 1.0, 1.0   # bob masses (kg)
theta1, theta2 = 2.0, 2.5  # starting angles (radians)
omega1, omega2 = 0.0, 0.0  # angular speeds

pivot = vector(0, 1, 0)
sphere(pos=pivot, radius=0.05, color=color.white)
bob1 = sphere(radius=0.08, color=color.red)
bob2 = sphere(radius=0.08, color=color.cyan, make_trail=True, retain=1500, trail_radius=0.01)
rod1 = cylinder(pos=pivot, radius=0.015, color=color.gray(0.7))
rod2 = cylinder(radius=0.015, color=color.gray(0.7))


def place():
    bob1.pos = pivot + L1 * vector(sin(theta1), -cos(theta1), 0)
    bob2.pos = bob1.pos + L2 * vector(sin(theta2), -cos(theta2), 0)
    rod1.axis = bob1.pos - pivot
    rod2.pos = bob1.pos
    rod2.axis = bob2.pos - bob1.pos


place()
dt = 0.0005
while True:
    rate(100)
    for _ in range(20):  # 20 small steps per frame: accurate and still real time
        d = theta1 - theta2
        den = 2 * m1 + m2 - m2 * cos(2 * d)
        alpha1 = (-g * (2 * m1 + m2) * sin(theta1) - m2 * g * sin(theta1 - 2 * theta2)
                  - 2 * sin(d) * m2 * (omega2 ** 2 * L2 + omega1 ** 2 * L1 * cos(d))) / (L1 * den)
        alpha2 = (2 * sin(d) * (omega1 ** 2 * L1 * (m1 + m2) + g * (m1 + m2) * cos(theta1)
                  + omega2 ** 2 * L2 * m2 * cos(d))) / (L2 * den)
        omega1 += alpha1 * dt
        omega2 += alpha2 * dt
        theta1 += omega1 * dt
        theta2 += omega2 * dt
    place()
```

Change a starting angle by just 0.001 and after a few seconds the motion looks completely different. That sensitivity is what makes it chaotic. Doing several small physics steps per `rate()` frame keeps it accurate without slowing it down: 100 frames × 20 steps × 0.0005 s = 1 second per second.

Make a box full of gas particles bouncing around in VPython.
<<<PROMPT>>>
Simulate many balls bouncing inside a 3D box in VPython.
<<<ANSWER>>>
Each particle moves in a straight line and bounces off the walls. A see-through box shows the container:

```python
from vpython import *

scene.title = "Gas particles in a box"
L = 10          # side of the box
N = 40          # number of particles
r = 0.25        # particle radius
half = L / 2 - r  # how far a particle's center can go from the middle

box(pos=vector(0, 0, 0), size=vector(L, L, L), opacity=0.15, color=color.white)

particles = []
for i in range(N):
    p = sphere(pos=vector.random() * half, radius=r,
               color=color.hsv_to_rgb(vector(random(), 0.7, 1)))
    p.velocity = vector.random() * 5
    particles.append(p)

dt = 0.01
while True:
    rate(100)
    for p in particles:
        p.pos = p.pos + p.velocity * dt
        # Bounce: point the velocity back into the box
        if p.pos.x > half:
            p.velocity.x = -abs(p.velocity.x)
        elif p.pos.x < -half:
            p.velocity.x = abs(p.velocity.x)
        if p.pos.y > half:
            p.velocity.y = -abs(p.velocity.y)
        elif p.pos.y < -half:
            p.velocity.y = abs(p.velocity.y)
        if p.pos.z > half:
            p.velocity.z = -abs(p.velocity.z)
        elif p.pos.z < -half:
            p.velocity.z = abs(p.velocity.z)
```

How it works:
- `vector.random()` gives random positions and directions; multiplying scales them.
- Setting the velocity with `abs()` always points it back inside, so particles never get stuck in a wall.
- The particles don't hit each other here. That's a fine model of an ideal gas, where the particles almost never meet.

```python
while True:
    rate(30)
    t += dt
    for tile in tiles:
```

<<<PROMPT>>>
Simulate a rocket launch in VPython where the rocket burns fuel and gets lighter. Graph the altitude.
<<<ANSWER>>>
Thrust = fuel burn rate × exhaust speed. As fuel burns, the mass drops, so the same thrust gives more and more acceleration. After the fuel runs out, the rocket coasts up and falls back:

```python
from vpython import *

scene.title = "Rocket launch (no air resistance)"
scene.range = 30

ground = box(pos=vector(0, -1, 0), size=vector(60, 2, 20), color=color.green)
body = cylinder(pos=vector(0, 0, 0), axis=vector(0, 8, 0), radius=1, color=color.white)
nose = cone(pos=vector(0, 8, 0), axis=vector(0, 3, 0), radius=1, color=color.red)
rocket = compound([body, nose])
flame = cone(pos=vector(0, 0, 0), axis=vector(0, -4, 0), radius=0.8, color=color.orange, emissive=True)
scene.camera.follow(rocket)
readout = label(pos=rocket.pos, text="", xoffset=80, yoffset=40, height=13)

g = 9.8
dry_mass = 300.0      # kg without fuel
fuel = 700.0          # kg
burn_rate = 10.0      # kg/s
exhaust_speed = 2500  # m/s
altitude = 0.0        # m (the scene shows it in units of 100 m)
velocity = 0.0        # m/s

plot = graph(title="Altitude", xtitle="t (s)", ytitle="altitude (km)", height=250)
alt_curve = gcurve(graph=plot, color=color.blue)

dt = 0.1
t = 0
while altitude >= 0:
    rate(200)
    if fuel > 0:
        thrust = burn_rate * exhaust_speed
        fuel = max(0.0, fuel - burn_rate * dt)
    else:
        thrust = 0
        flame.visible = False
    mass = dry_mass + fuel
    acceleration = (thrust - mass * g) / mass
    velocity += acceleration * dt
    altitude += velocity * dt
    t += dt

    rocket.pos = vector(0, altitude / 100 + 5.5, 0)
    flame.pos = vector(0, altitude / 100, 0)
    readout.pos = rocket.pos
    readout.text = f"t = {t:.0f} s\naltitude {altitude / 1000:.1f} km\nspeed {velocity:.0f} m/s\nfuel {fuel:.0f} kg"
    alt_curve.plot(t, altitude / 1000)

print(f"Landed after {t:.0f} s")
```

How it works:
- `thrust - mass * g` is the net upward force, and dividing by the *current* mass gives the acceleration, so it grows as the fuel burns.
- The scene uses 1 unit = 100 m so the motion fits on screen, while the physics uses real meters.
- Without air resistance this rocket goes very high; adding a drag force like `-0.5 * c * velocity * abs(velocity)` would be the next step.

<<<PROMPT>>>
Draw the Lorenz attractor in VPython.
<<<ANSWER>>>
The Lorenz system is three linked equations that never settle and never repeat. Drawing its path with a `curve` gives the famous butterfly shape:

```python
from vpython import *

scene.title = "Lorenz attractor"
scene.background = color.black
scene.center = vector(0, 0, 25)
scene.forward = vector(-1, -0.3, -1)

sigma, rho, beta = 10, 28, 8 / 3
x, y, z = 1.0, 1.0, 1.0

path = curve(radius=0.15, retain=4000)
tip = sphere(pos=vector(x, y, z), radius=0.5, color=color.white, emissive=True)

dt = 0.005
t = 0
while True:
    rate(300)
    dx = sigma * (y - x)
    dy = x * (rho - z) - y
    dz = x * y - beta * z
    x, y, z = x + dx * dt, y + dy * dt, z + dz * dt
    t += dt

    point = vector(x, y, z)
    path.append(pos=point, color=color.hsv_to_rgb(vector((t * 0.02) % 1, 1, 1)))
    tip.pos = point
```

How it works:
- `sigma`, `rho` and `beta` are Lorenz's classic values; with them the path loops around two "wings" forever.
- `curve.append(pos=..., color=...)` gives each point its own color, so the hue shows how old each part of the path is.
- `retain=4000` keeps only the newest points, which stops the program from slowing down over time.

```python
    total_arrow.axis = momentum
    ke = 0.5 * puck1.mass * mag2(puck1.velocity) + 0.5 * puck2.mass * mag2(puck2.velocity)
    info.text = f"total momentum ({momentum.x:.2f}, {momentum.y:.2f})   kinetic energy {ke:.2f}"
```

The yellow arrow (total momentum) doesn't change at the collision, but the kinetic energy drops. In a sticky collision some energy turns into heat and sound, while momentum is always conserved.
